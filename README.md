# SFTP 可视化指南

## 当前仓库状态

本仓库当前只包含 Next.js 静态导出/部署产物（例如 `index.html`、`_next/` 和导出的文本文件），**不包含原始 Next.js 源码、依赖清单/锁文件或构建配置**。检查现有本地分支及可达 Git 历史后，没有找到这些源文件，因此无法从仓库历史安全恢复源码，也无法确认可复现的源码构建步骤。请勿把压缩后的浏览器 JavaScript 当作原始源码进行还原；本仓库静态导出物保持未修改。

## 当前静态预览

在仓库根目录启动只绑定本机的静态 HTTP 服务：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

然后在本机浏览器打开 <http://127.0.0.1:8000/>。按 `Ctrl+C` 停止服务。直接双击 `index.html` 也可能预览，但 HTTP 服务更适合加载页面资源。

此方法只预览已提交的静态导出物，**不是源码构建**，不能用于生成或验证新的应用版本。

## 需要从原开发环境或备份找回

要恢复可维护、可复现的源码构建，请从原开发环境、版本控制备份或项目归档中找回并核验：

- Next.js 应用源码目录（如 `app/` 或 `pages/`，以及项目实际使用的 `components/`、`lib/`、样式和公共资源）；
- `package.json` 及原始包管理器锁文件（例如 `package-lock.json`、`pnpm-lock.yaml` 或 `yarn.lock`；以原项目实际使用者为准）；
- Next.js、TypeScript、Tailwind CSS、PostCSS 等实际使用的配置文件（若项目存在）；
- `.npmrc` 等影响依赖解析或构建的非秘密配置（若项目存在）；
- 原始 Node.js 与包管理器版本、构建命令、环境变量名称/说明，以及静态导出和部署配置；不得把秘密值提交到仓库；
- 原开发环境中的 README、构建/部署脚本及其余应用资源。

找回后应与可信备份核对完整性，并以原锁文件和原环境信息验证构建；在缺少这些证据前，不应猜测依赖版本或生成新的锁文件。

## 维护风险

- 静态产物不可替代源代码；功能修改、缺陷修复和安全更新无法从本仓库以可信方式完成。
- 依赖版本、构建命令、环境配置和部署流程均未记录，当前无法复现产物。
- 直接编辑导出的 HTML/JS/CSS 容易导致不一致或被下次导出覆盖；应先找回并验证原始源码及构建环境，再以源码为维护入口。
- 在源码恢复前，静态预览仅可用于检查现存导出内容，不代表当前依赖或应用实现经过安全维护。
